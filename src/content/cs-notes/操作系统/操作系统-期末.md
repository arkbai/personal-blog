## 2.2 进程控制
>用**原语**实现
>PCB的进程状态（state）是进程控制的关键

**原语**具有原子性，不允许中断，通过2条特权指令（<u>关中断指令，开中断指令</u>）来取消中断检查

1. 进程创建——创建原语
	（*用户登录，作业调度，提供服务，应用请求*）
	- 申请PCB
	- 为新进程分配资源，初始化PCB
	- 把PCB插入就绪队列（创建->就绪）
2. 进程终止——撤销原语
	 （*正常结束exit，异常结束，用户关闭*）
	- 从PCB集合中找到对应PCB
	- 剥夺CPU，终止其子进程，释放资源
	- 删除PCB
3. 进程阻塞——阻塞原语
	（*等待分配资源或者其他进程*）
	- 停止运行，保存现场信息到PCB中，运行->阻塞
4. 进程唤醒——唤醒原语
	（*结束等待*）
	- 把PCB移出阻塞队列，阻塞->就绪
5. 进程切换——切换原语
	（*时间片，换为高优先级，当前进程主动阻塞/终止*）
	- 将<u>运行环境</u>信息存入PCB
	- PCB移入对应的队列以后，执行另一个进程
	- 根据PCB恢复新进程所需的<u>运行环境</u>
### ==Linux进程控制==
进程创建：fork（）——如果不终止，第二次将会创建子进程：进程终止：exit（）
1. 在父进程中，fork()返回新创建子进程的进程ID。    
2. 在子进程中，fork()返回0。
3. 如果出现错误，fork()返回一个负值。

>fork()函数的执行过程
> 
> 1. **申请PID**：为新进程申请一个唯一的进程ID。
> 2. **申请PCB结构**：为新进程申请一个进程控制块（PCB）。
> 3. **复制父进程的PCB**：将父进程的PCB复制到新进程中。
> 4. **设置子进程的运行状态**：将子进程的运行状态设置为不可执行的。
> 5. **清零和保留某些属性**：将子进程中的某些属性清零，某些保留，某些修改。
> 6. **复制父进程的页**：使用写时拷贝技术，初始阶段父子进程共享所有的数据，当任意一个进程试图修改数据时，内核才会将要修改的数据所在的区域拷贝一份。

- 临界资源：一次只有一个进程使用的资源，可划分为，<u>进入区、临界区、退出区、剩余区</u>
 - 互斥访问的原则：<u>空闲让进、忙则等待、有限等待、让权等待</u>
### 进程同步与互斥机制
1. 硬件方法
	1. 中断屏蔽：用特权指令（关中断，开中断）实现，单cpu
	2. TestAndSet（TS/TSL指令）

	3. Swap指令（Exchange指令）
		<img src="images/Pasted%20image%2020260103222150.webp" width="270">
2. 软件方法
	 1. 单标志法：每个进程访问完临界区后，把权限交给下一个，
		 while(turn!=0); ...... turn=1;......while(turn!=1);......
	 2. 双标志先检查：设置flag\[2]，标记各进程进入临界区的意愿
	 3. 双标志后检查：先上锁后检查，（违背了空闲让进和有限等待）
	 4. Peterson算法：结合单，双标志法，“主动争取，主动谦让，先谦让的会先执行”
```C
//p0
void process0()
{
    interested[0] = true;//表明p0想访问临界区
    turn = 0;//表示当前由p0进入
    while(turn == 0 && interested[1] == true) {;} //在此阻塞
    //若p1当前不想访问，阻塞结束
    //临界区
    interested[0] = false;
}
//p1
void process1()
{
    interested[1] = true;
    turn = 1;
    while(turn == 1 && interested[0] == true) {;} //在此阻塞
    //临界区
    interested[1] = false;
}
```
3. 锁机制
	- 互斥锁：进程进入临界区获得锁，退出时释放锁，缺点是其他进程会忙等待（一直调用获得锁的函数），所以互斥锁通常用于<u>多处理器系统</u>
	- 自旋锁spin lock：需要连续循环忙等待的互斥锁（TSL、Swap、单标志法）
4. ==信号量机制==
	>信号量 Semaphore
	>进入区的检查上锁操作不能一次完成；其他所有方法都不能实现让权等待

	- 整型信号量：整型S，P{S循环-=1}，V{S+=1}，缺点是进程没有资源时会<u>忙等</u>
	- **记录型信号量**：semaphore{value，L}，没有资源时阻塞

## 2.4 进程调度
>系统按照一定原则选择某些作业或进程来占用资源运行
>狭义进程调度 vs 进程切换：狭义的进程调度是分配cpu资源给进程，进程切换是 保存现在进程状态 和 恢复另一个进程状态 的操作

- 调度程序：实现调度算法，处理对象是进程（或内核级线程）
- 闲逛进程idle：优先级最低，占一个指令周期，没有就绪进程时就执行《让cpu不能闲着》
### 分类
- 高级调度（作业调度）：作业~=程序，从作业队列中选择作业调入内存，作业调入时创建PCB，调出时撤销PCB，作业>进程，（<u>系统可以同时处理多道作业但是只能运行单个进程，这时需同时考虑作业调度与进程调度</u>）
- 中级调度（内存调度）：将PCB先挂起调到外存，组成挂起队列；因此可增加两种进程状态，就绪挂起 / 阻塞挂起
- 低级调度（**进程调度**）：就绪->运行
### 进程调度的时机
<img src="images/Pasted%20image%2020260103171735.webp" width="530">
### 进程调度方式
1. 非抢占方式：除非进程阻塞或终止，否则不会被打断（批处理）
2. 抢占方式：（分时、实时）
### ==进程调度算法==
1. 先来先服务调度算法（FCFS）：利于长作业，非抢占
2. 短作业优先（SJF）：对短作业有利，会出现饥饿现象，非抢占
3. 高响应比优先（HRRN）：响应比 = (等待时间+要求执行时间）/ 要求执行时间；每次都要计算响应比，增加系统开销，非抢占
4. 优先级（RR）：分为**静态**和**动态**优先级
	- 动态优先级的设置：等待时间越长优先级越高，运行时间越长优先级越小
5. 时间片轮转：当前时间片用完了就令进程到队列中重新排队，（未用完时间片则直接运行下一个）提高响应速度，用户友好，抢占
6. 多级队列调度算法：优先级从高到低，系统进程-交互式进程-批处理进程，各队列可采用不同的调度策略，如交互式RR，批处理FCFS
7. <u>多级反馈队列调度算法</u>：抢占
	<img src="images/Pasted%20image%2020260103175847.webp" width="420">
	- 设置多级就绪队列，各级队列优先级从高到低，时间片从小到大（1、2、4......）
	- 新进程到达时先进入第1级队列，按FCFS原则排队等待被分配时间片，若用完时间片进程还未结束，则进程进入下一级队列队尾。 如果此时已经是在最下级的队列，则重新放回该队列队尾
	- 只有第k级队列为空时，才会为k+1级队头的进程分配时间片
### 调度算法的评价指标
- cpu利用率 = cpu工作时间 / 总时间
- 系统吞吐量 = 作业数量 / 总时间
- **==周转时间==** \= <u>作业提交到完成的总时间</u>
- 平均周转时间 = 各个作业的周转时间和 / 作业数量
- 带权周转时间 = 周转时间 / 要求执行时间
- 等待时间
- 响应时间

### 多处理机调度
>单处理机调度：只需决定哪个就绪进程优先进入cpu
>多处理机调度：还需决定进入哪个cpu

目标：
1. 负载均衡：每个cpu同等忙碌
2. 处理器亲和性：尽量使一个进程在同一个cpu上运行，cache
	
方案：
1. 公共就绪队列：所有cpu共享一个就绪进程队列，每个cpu运行调度程序来选择，负载均衡好
	- 软亲和：进程调度程序
	- 硬亲和：用户进程通过系统调用控制分配的cpu
2. 私有就绪队列：每个cpu都有一个队列，亲和性好
	- 推迁移push策略：负载高的推给别的cpu
	- 拉迁移pull策略：负载低的拉进程

## 2.6 进程死锁
>死锁的原因：各进程竞争资源，进程推进顺序不当
### 产生死锁的必要条件 和 破坏方法
- 互斥——将临界资源改造成共享资源
- 占用且等待（请求和保持）——提取分配好所有资源
- 不可剥夺——1. 申请资源失败时立即释放所有资源 2. 申请资源被其他进程占用时，由操作系统按优先级抢占
- 循环等待——编号，严格按顺序申请资源
### 处理死锁的方法
1. **静态：预防死锁**
	预防死锁的目标是破坏一个必要条件，如SPOOLing技术破坏<u>互斥条件</u>，将独占设备逻辑上变为共享设备
	
2. **动态：避免死锁**
	**银行家算法**
	- 安全序列：系统按顺序分配资源，每个进程都顺利完成
	- 安全状态：存在安全序列 / 不安全状态：不存在
	- 安全序列的计算⬇(3,3,2)->(5,3,2) 大于 (1,2,2) 
	![](images/Pasted%20image%2020260104211236.webp)
	
3. **检测和解除死锁**
	1. 资源分配图
	<img src="images/Pasted%20image%2020260104211947.webp" width="300">
	2. **死锁检测算法**
		- 死锁定理：消去所有的“<u>既不阻塞又不独立</u>”的进程节点的边，如果所有节点都变成独立的，那么称该图可完全简化，此时没有死锁发生
	3. 死锁的解除
		- 资源剥夺法
		- 撤销进程法

| 1   | 2MB  | 8M   | 空闲  |
- 空闲分区链

1. **首次适应算法**
算法思想：空闲分区按起始地址递增依次链接，每次从低地址开始查找，找到第一个能满足大小的空闲分区
<u>算法开销最小</u>

2. **最佳适应算法**
算法思想：为了保证“大进程”到来时能有连续的大片区域，可以尽可能留下大片的空闲区
优先使用**更小**的空闲区，空闲分区按容量**递增**次序链接，分配内存时<u>顺序查找</u>空闲分区链
<img src="images/Pasted%20image%2020260104221824.webp" width="350">
缺点：会留下小碎片

3. **最坏适应算法**
算法思想：和最佳适应算法相反，按容量**递减**次序排列，每次用**更大**的分区，从而增大剩余空间的可利用率

4. **领近适应算法**
算法思想：每次从上次查找结束的位置开始检索，空闲分区排成**循环链表**，每次从指针位置查找
算法开销小
缺点：大空间容易被用完
## 3.4 ==分页存储管理方式==
>将所有内存物理空间和程序逻辑空间分为大小相等的块
>逻辑空间：页、页面（2<sup>k</sup>B 方便得到页号与起始地址）
>物理空间：物理块=页框=页帧=内存块=物理页面
>地址是一维的

### 地址映射
- 逻辑地址结构：【页号+页内偏移量】
- 页表：页面（逻辑空间）——物理块（物理空间），页表的起始地址及长度信息存储在进程的PCB中
	<img src="images/Pasted%20image%2020260104222816.webp" width="202">
	
- **计算**
	页号 = 逻辑地址 / 页面大小（**取整**）
	页内地址 = 逻辑地址 % 页面大小（**取余**）
	物理地址 = 页面对应物理块号 x 页面大小 + 业内地址
	【 块数 = 物理内存4GB/页面大小4KB = 2<sup>20</sup> 】
	块号所占空间 = 20bit <= 24bit = 3B
	页号是隐含的，可计算但不占空间

- **地址映射过程**：
<img src="images/Pasted%20image%2020260104224650.webp" width="890">
- 页表寄存器（PTR）：存放页表的起始地址F和长度M，进程执行时，从PCB中将F、M放入PTR
- 越界中断：页号 > 页表长度M时，执行中断

### 快表（TLB）
>又称联想寄存器（TLB），是一种访问速度比内存快很多的高速缓冲存储器，用来存放当前访问的若干页表项，以加速地址变换的过程。类似cache，利用局部性原理

访存时间 = 75% x 访问内存100us + 25% x （<u>访存页表100us +访问单元100us</u>【2次】 + 访问快表时间1ns）

### 两级和多级页表
>当物理空间被划分为时2<sup>20</sup>块时，需要长度为1024x1024的页表，太长了，
>可以采用两级页表：页目录表（1024个页表项）--二级页表（1024个对应块号）

- 逻辑地址结构：一级页号+二级页号+......+页内偏移量 ![](images/Pasted%20image%2020260106211422.webp)
- 各级页表大小不能超过页面大小 ![](images/Pasted%20image%2020260106211019.webp)
- 每次地址映射都需要访问内存，所以需要<u>快表</u>来提高访存性能

- 段是逻辑单位，对用户是可见的，长度是用户定义的，二维（段名+偏移）

- 工作集：指在某段时间间隔里，进程实际访问页面的集合，根据工作集大小确定驻留集大小

## 5.3 文件的结构和存取
>**文件存取方式**：顺序存取：平均访问次数=对应块/2，随机存取：访问次数=1
### 逻辑结构
- 有结构文件：“纪录式文件”，如数据库文件
	1. 顺序：定长/不定长，顺序/链式
	2. 索引：定长，随机访问
	3. 索引顺序：由索引表组织
	4. 直接：键值转换
	5. 散列：hash函数
- 无结构文件：流式文件.txt

### 物理结构（文件分配方式）
>内存管理中，逻辑地址分为页，外存中，文件的逻辑地址也分为文件块，从而对应磁盘块
>逻辑地址 = 逻辑块号，块内地址
>操作系统实现逻辑地址到物理地址的映射

1. 连续文件：物理块号 = 起始块号 + 逻辑块号
	- 优点：顺序访问磁盘块，磁头移动短，读写速度快；可随机存取；
	- 缺点：磁盘碎片多；不方便扩展
2. 链接文件：
		使用不连续的磁盘块，方便经常修改，易失
	- **隐式链接**：只能顺序访问，查找效率低
	- **显式链接**：使用**文件分配表 FAT**，检索速度快，可随机存取；但FAT表大时效率低
		<img src="images/Pasted%20image%2020251224141650.webp" width="300">
	- ==FAT表的计算==：
		10MB，2<sup>5</sup>< 56块<2<sup>6</sup>，FAT = 56 \* (6位/8=0.75~=1)B
3. 索引文件：使用**索引表**【逻辑块号 | 物理块号】
	逻辑块号是隐式的，存放物理块号的叫<u>索引项</u>，对应的物理块叫<u>磁盘块</u>，可顺序，可随机
	- 单级 链接方法：将多个索引块链接起来
	- 多级索引：索引块中存储下一级的索引表地址
		 <img src="images/Pasted%20image%2020260106233748.webp" width="360">
	- **混合索引**：
		对于小文件，读磁盘次数少（unix、linux）
		![](images/Pasted%20image%2020260106235832.webp)
		- <u>最大文件大小 = (二级索引)256x256KB+(一级索引)256KB+(直接地址)8KB</u>

==多级索引和文件大小的计算==
- 磁盘块大小1KB，一个索引表项占4B，一磁盘块可放1KB/4B = 256个索引表项，则二级索引的最大长度 = 256x256x1KB = 64MB
- 访问1026逻辑块时，（与内存页类似）1026/256 = 4（一级索引号），1026%256 = 2（二级索引号）再访问数据块

## 5.4 文件存储空间管理
1. 空闲表法：为所有空闲分区建立空闲表：【序号 | 起始盘块号 | 空闲块数】
	- 分配磁盘块方法与内存*空闲分区分配算法*相似
	- 合并：回收空闲分区时查找邻接是否有空闲，若有则合并为一个更大的空闲分区
	- 空闲区域大则效率低
3. 空闲块链表法：为所有空闲分区建立链表
	- 每次都需I/O操作，效率低
4. **位示图**法：0空闲，1分配，（行号：字号，列号：位号），（1，9）->16x1+9=25块号
	<img src="images/Pasted%20image%2020260107211356.webp" width="450">
5. 成组链接法：大型文件系统，把所有空闲分区按组分配，每组组号指向下一组，直到指向-1时结束
	- 空闲盘块栈（首个为超级块）：【下一组空闲数 | 空闲组号n】

## 5.6 虚拟文件系统
>对于不同类型的文件系统（UFS、NTFS、FAT）需要不同的接口

可以建立虚拟文件系统VFS，提供了标准接口POSIX

	- 存储了文件信息 与 函数功能指针，指向具体文件系统的操作（read...）
	- v node只在主存中，具体文件系统目录表i node在内存与外存都有
- 文件系统挂载：
	- VFS中注册挂载表，包含了文件系统的信息
	- 文件系统向VFS中提供函数地址列表

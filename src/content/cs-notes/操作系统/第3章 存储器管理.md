# 一、存储器管理的概念
>- 按字节编址 / 按字编制（字长已知）
>- 逻辑地址（相对地址） / 物理地址（绝对地址）
>- 计算机存储系统：CPU内寄存器--Cache--内存--辅助存储器
### 1、程序的链接与装入
>编译—链接—装入
>- 编译：高级语言->机器语言
>- 地址重定位：逻辑地址->物理地址【虚拟内存系统，可以由内存管理单元自动完成】

- **程序的链接**：将目标模块与库函数合并为<u>装入模块</u>
	1. 静态链接：在程序运行前，先将各目标模块及它们所需的库函数连接成一个完整的可执行文件
	2. 装入时动态链接：边装入边链接（当遇到外部符号时，再查找并装入对应目标模块）
		- 便于修改，目标模块可共享
	3. 运行时动态链接：在程序执行中需要该模块时，才对它进行链接【for虚拟存储系统】
		- 加快装入过程，节省内存空间
- **程序的装入**：将<u>装入模块</u>载入内存
	1. 绝对装入（单批道）：内存中只有一个程序，在编译前就知道程序放在内存的哪个位置
	2. 静态重定位（多批道）：装入时将模块载入一块连续的内存区域，然后一次性将逻辑地址->物理地址
		- 需要提前分配好作业的内存空间，不能修改
	3. 动态重定位：指令执行时再由MMU进行地址重定位
		- 重定位寄存器：存放模块起始地址
		- 支持程序修改内存中的位置，提高内存分配的灵活性【紧凑技术】
		- <u>起始地址+最大逻辑地址（最大偏移）</u>
### 2、存储器管理功能
1. 内存空间的分配与回收：记录空闲区域方便回收
	- 分配方式的进化：连续分配【单一连续分配->固定分区分配->动态分区分配】->离散分配【分段式存储管理 / 分页式】
2. 内存空间的扩充：虚拟存储，从逻辑上扩充内存
3. 地址映射
	逻辑地址、虚地址、相对地址—>物理地址、实地址、绝对地址
4. 内存共享：共享库、进程间通信
	- 只有只读区域可以被共享
	- **可重入代码**：可以被多个进程同时访问但是不允许修改
5. 内存保护：确保进程只能访问自身授权的内存
	- 上下限寄存器：记录进程上下限地址，cpu每次访问地址都判断地址越界
	- 重定位寄存器（基址寄存器）：记录起始地址
	- 界地址寄存器（限长寄存器）：记录地址空间长度，和逻辑地址进行比较，判断地址越界

# 二、 连续存储器管理方式
> 用户进程在主存中以连续方式存放
> 内部碎片：分配给进程的内存区域中，没有用上的部分
> 外部碎片：内存中的空闲分区
### 1. 单一连续分配
>单用户，单任务的操作系统，只有一整块用户区

- 简单，无外部碎片，有内部碎片，内存利用率低
### 2. 固定分区方式
>多道程序，将用用户空间分割为若干固定分区给各道程序
>- 分区大小相等：一台计算机管理多个相同对象
> - 分区大小不相等：灵活
>	<img src="images/QQ_1788186049388.webp" width="219">
>- 分区说明表
>	<img src="images/QQ_1788186174485.webp" width="305">

- 简单，无外部碎片，有内部碎片（作业小于分区）
- 多个进程无法共享同一区域
### 3. 动态分区方式
>进程装入内存时，根据进程大小动态地建立分区

- 初期利用率高，但随着进程装入与释放，会出现较多空闲区域——无内部碎片，有外部碎片
	<img src="images/QQ_1788186704037.webp" width="210">
- 回收内存时可能的情况：
	1. 回收区前有空闲分区：合并，更新分区1的大小
	2. 回收区后有空闲分区：合并，更新分区2的起始地址和大小
	3. 前后都有空闲：合并，更新分区1大小，删除分区3的表项
	4. 前后都没有：新建表项
- **紧凑技术**：周期性移动进程，把空闲块合并为连续区域【需要动态重定位实现进程的移动】

### 动态分区分配算法
1. **首次适应算法**
	- 空闲分区按起始地址递增依次链接，每次从低地址开始查找，找到第一个能满足大小的空闲分区
	- 缺点：每次先用低地址，容易产生小碎片

2. **领近适应算法**
	- 每次从上次查找结束的位置开始检索，空闲分区排成**循环链表**，每次从指针位置查找
		<img src="images/QQ_1788188491359.webp" width="362">
	- 减少了查找开销，令高-低地址等概率被使用
	- 缺点：大空间容易被先用完，产生外部碎片

3. **最佳适应算法**
	- 优先使用**更小**的空闲区，空闲分区按容量**递增**次序链接，分配内存时<u>顺序查找</u>空闲分区链
		<img src="images/Pasted%20image%2020260104221824.webp" width="350">
	- 为了保证“大进程”到来时能有连续的大片区域，尽可能留下大片的空闲区
	- 缺点：会留下外部碎片

4. **最坏适应算法**
	- 优先用**更大**的分区，空闲分区按容量**递减**次序排列
	- 增大剩余空间的可利用率
	- 缺点：难以满足“大进程”的要求

# 三、分页存储管理方式
>将所有内存物理空间和程序逻辑空间分为大小相等的块
>逻辑空间：页、页面（2<sup>k</sup>B 方便得到页号与起始地址）
>物理空间：物理块=页框=页帧=内存块=物理页面
>地址是一维的
>- 提高内存利用效率，消除外部碎片，页面大小固定--有内部碎片

### 分页式地址映射
- 逻辑地址结构：【页号、页内偏移量】
- **页表**：页面——物理块
	<img src="images/Pasted%20image%2020260104222816.webp" width="202">
	- 系统为每个进程建立一张页表
	- 进程的每个页面对应一个页表项
	- 页表的起始地址及长度信息存储在进程的PCB中

- **计算**：
	- 页号 = 逻辑地址 / 页面大小（**取整**）
	- 页内偏移 = 逻辑地址 % 页面大小（**取余**）
	- 页内偏移位数 = log<sub>2</sub>（页面大小）
	- 物理地址 = 页面对应物理块号 x 页面大小 + 页内偏移
	- 总物理块数 = 物理内存4GB/页面大小4KB = 2<sup>20</sup>
		- 存储块号所占空间 = 20bit <= 24bit = 3B
		- 页号是隐含的，不占空间

> 页面大小取2<sup>k</sup>利于计算机硬件识别逻辑地址
> <img src="images/QQ_1788192052484.webp" width="489">
-------------
- **基本地址变化机构**：
	<img src="images/Pasted%20image%2020260104224650.webp" width="890">
	- 页表寄存器PTR：存放页表的起始地址F和长度M，进程执行时，从PCB中将页表信息放入PTR
	- 越界中断：页号 > 页表长度M时，执行中断
	- 查找页表 由内存管理单元（MMU）自动完成

### 快表（TLB）
>又称联想寄存器（TLB），是一种访问速度比内存快 的高速缓冲存储器，用来存放当前访问的若干**页表项**，以加速地址变换的过程
>快表命中时，只需要一次访存就可以得到页面的物理地址
>类似cache，利用局部性原理

- **访存时间** = **命中率**75% x (**访存时间**100us+**访问快表时间**1us) **+** 25% x（**（页表）访存时间**100us +访存时间100us + 访问快表时间1us）
- 可同时查询快表与页表⤵
	<img src="images/QQ_1788243228841.webp" width="577">
- 页面大小++ 页表项数量-- 命中率++
### 多级页表
>当物理空间被划分为时2<sup>20</sup>块时，需要长度为1024x1024的页表，页表本身占用太大，而且无需让整个页表常驻内存
>- 采用两级页表：页目录表（1024个页表项）--二级页表（1024个对应块号）
>- 虚拟存储：访问时才将页面调入内存
>	- 标志位：判断页面是否已调入内存

- 逻辑地址结构：一级页号+二级页号+......+页内偏移量 <img src="images/Pasted%20image%2020260106211422.webp" width="492">
	<img src="images/QQ_1788243851260.webp" width="658">
- 判断采用几级页表——令各级页表大小<页面大小，即每级页表存的页表项数量不能超过上限⤵<img src="images/Pasted%20image%2020260106211019.webp" width="712">
	<img src="images/QQ_1788244231319.webp" width="535">
- 每次地址映射都需要访问内存，所以需要<u>快表</u>来提高访存性能
# 四、分段存储管理方式
>将进程的逻辑地址空间划分为若干个段
>每个段在内存中连续，但各个段之间可以不相邻
>二维的非线性地址空间
><img src="images/QQ_1788247259006.webp" width="312">

### 分段式地址映射
- 物理地址 = 基址 ~ 基址+段长
- 逻辑地址结构：【段号，段内地址】
- **段表**
	- 每个段表项长度固定，eg:物理内存4GB->基址32位
	- 段号隐含，不占空间
	<img src="images/Pasted%20image%2020260106212415.webp" width="218">
- **基本地址变化机构**
	![](images/QQ_1788247525404.webp)
	- 段表寄存器：存储段表基址F和段表长度M，检查越界
	- 越界保护：偏移<段长
	- 存取控制保护：段表项中的访问权限位
### 分页与分段方式的对比
- 分段比分页更容易实现信息的共享和保护
- 页是物理单位，对用户是不可见的，长度是系统决定的，一维（页）
- 段是逻辑单位，对用户是可见的，长度是用户定义的，二维（段名+偏移）
- 单级页表与分段都需要两次访存
### 段共享
> 分段比分页更容易实现共享，只需设置一个共享段（纯代码/可重入代码）实现对一段代码或数据的共享

- 共享段表项的组成：段号、段长、内存基址、存在位、外存基址、共享进程数count
- 同一共享段在不同进程中有不同的段号
# 五、段页式存储管理方式

# 六、虚拟存储系统
>传统存储管理方式（连续 / 非连续）具有一次性、驻留性（需要一次将全部作业装入内存，作业会一直常驻）
>基于局部性原理，将有用的部分调入内存，用不到的换入外存，从而产生了一个虚拟的内存空间

- 特征：多次性、对换性、虚拟性
- 实现方式：**请求分页**、请求分段、请求段页式
- 硬件支持：页/段表机制、中断机构、地址变换机构
## 1、请求分页管理方式
> - ‘请求调页’：如果访问的页框在外存中，则请求从外存调入
> - ‘页面置换’：暂时不用的页框换出外存

- 页表：（与基本分页相比，请求分页增加了4个字段⤵）
	1. 状态位P：是否已调入内存
	2. 访问字段A：最近被访问次数（用于页面置换）
	3. 修改位M（脏位）：页面调入后是否被修改（用于写回外存）
	4. 外存地址
		<img src="images/Pasted%20image%2020260106215510.webp" width="500">
- 计算：（与物理空间大小无关）与基本分页方式相同
- **缺页中断机构**
	- 当访进程问的页面状态位=0（页面不在内存中）就触发<u>缺页中断处理程序</u>，缺页中断属于<u>内中断</u>
		- 如果内存存在空闲块，则为进程分配一个空闲块，把页面从外存调入，更新页表
		- 如果没有空闲块，则由**页面置换算法**淘汰一个页面（如果被淘汰页面修改位=1，则需要写回外存），然后再把页面从外存调入，更新页表
> 页面调入为磁盘I/O操作，系统可以调度其他进程运行
- 地址变换机构（映射过程）：
	- 1-检索快表TLB
		- 2-若命中，取出物理块号，访问位=1
			- 若进程执行写操作，令修改位=1
		- 3-若未命中，访问页表
			- 4-若状态位=1，则取出物理块号，将对应页表项装入快表；装入时若快表已满，则进行置换算法
			- 5-若状态位=0，则触发缺页中断；更新快表与页表，然后跳转回1-（此时快表一定命中）
		<img src="images/QQ_1788329523006.webp" width="615">
		请求分页增加部分—<img src="images/QQ_1788330430896.webp" width="439">

## 2、页框的分配
### (1) 页面分配策略
> 驻留集：请求分页管理中，给进程分配的内存物理块集合，通常小于进程大小
> - 驻留集太小-缺页频繁
> - 驻留集太大-并发度低，资源利用率低

1. 固定分配局部置换
	- 固定：驻留集大小不变
	- 局部：发生缺页时只置换进程自己已分配的物理块
	- 需要合理分配初始驻留集⤵
> 页框调入算法：
> 1. 平均分配：页框数 / 进程数
> 2. 按比例分配：根据进程的逻辑地址空间大小分配
> 3. 优先权分配
2. 可变分配全局置换
	- 可变：驻留集大小可变
	- 全局：可以置换内存中所有的空闲块
	- 缺页->增加物理块；驻留集可能持续膨胀
3. 可变分配局部置换
	- 缺页率低--回收页框 / 缺页率高--增加页框
	- 增加了开销，但是保持较高的并发度与效率



> - \*抖动现象（颠簸）：刚刚换出的又要换入，刚刚换入的又要换出——分配的物理块不足
> - \*工作集：指在某段时间间隔里，进程实际访问页面的集合，令驻留集<工作集

## 5、页框回收

> 页式虚拟存储系统的性能-->页面换入换出的开销
> - 页面置换算法的选择
> - 磁盘内容读入内存频率
> - 已修改页面写回磁盘频率

**页面缓冲算法**： 在页面置换后加入‘修改页面链表’，以降低写回磁盘的频率

1. 空闲页面链表
	- 分配页框：进程读入页面时，从该链表中取出页框
	- **回收页框**：当进程将页面换出时，对于<u>未被修改</u>的页面，不将其写回磁盘，而是将页框插到链表尾
> 当系统分配的内存不足，或空闲页框数量低于一定值时，需要回收页框
> 内核的页框不可回收，进程的页框基本可回收
2. 修改页面链表：保存已修改的页面【**脏页**】，当‘待修改页面’数量达到一定值时，批量写回磁盘

## 6、虚拟存储的性能
> 缺页率

1. 页面大小++，缺页率--，页内碎片变大（单次可访问更多区域）
2. 分配给进程的页框数量++，缺页率--（进程更容易在内存中找到物理块，即提升内存命中率）
3. 页面置换算法，LRU、CLOCK缺页率较低
4. 页面写回磁盘频率（页面缓冲算法⤴）
5. 程序的局部化程度++，缺页率--

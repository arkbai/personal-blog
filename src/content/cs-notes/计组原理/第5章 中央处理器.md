# 一、CPU的功能与基本结构
1. 指令控制：取指令、分析指令、执行指令——指令的顺序控制
2. 操作控制：管理操作信号，将其送入相应的部件
3. 时间控制
4. 数据加工：算数逻辑运算
5. 中断处理

- 运算器：数据加工
	1. 算数逻辑单元ALU
	2. 通用寄存器组：SP堆栈指针；R0、R1...（也写作Ax、Bx... ）【如x86中，AH表示寄存器高位，AL表示低位】
	3. 暂存寄存器：配合ALU运算
	4. 累加寄存器ACC
	5. 程序状态字寄存器PSW：存储如ZF、OP、SP、CF等标志位
- 控制器：指令控制；中断处理
	1. 程序计数器PC：自增
	2. 指令寄存器IR：存储指令
	3. 存储器地址寄存器MAR：存放主存单元地址
	4. 存储器数据寄存器MDR：存放主存读写信息
	5. 指令译码器ID：操作码译码
	6. 微操作信号发生器：根据IR、PSW、时序信号产生控制信号
		- 分为组合逻辑型与存储逻辑型——对应硬布线与微程序
	7. 时序系统：由CLOCK分频得到
		<img src="/personal-blog/images/QQ_1782457672058.png" width="660">
	- <u>控制单元CU</u>：指令译码ID+微操作信号+时序系统
	- 用户可编程的寄存器：PSW、PC、通用寄存器组
# 二、指令执行过程
### 1、指令周期
> CPU从主存中取出并执行一条指令的时间
> 一条指令由1~4个指令周期组成，每个周期由一系列微操作构成

- **指令周期** & **机器周期** & **时钟周期（节拍）**

- 每个指令周期内的机器周期数可能不等⬇

### 3、指令执行方案
> 一个指令周期一般需要经过几个步骤才能完成指令的功能（取指、执行...）
> 指令执行方案：规划指令的步骤数

1. 单指令周期：所有指令使用相同的执行时间，指令之间串行
	- 指令周期=时钟周期，以时间最长的为准——运行效率低
	- CPI=1
2. 多指令周期：不同类型指令采用不同步骤，指令之间串行
	- 硬件设计较复杂
3. **流水线方案**：每一个时钟周期启动一条指令，多条指令并行
	- 第一条指令的取指周期完成后，取指对应的硬件空闲，可以执行第二条指令的取指周期

## 硬布线控制器  
> \*不考电路设计
> 也称**组合逻辑**控制器，先写出输出信号的逻辑表达式，再设计实际电路

- **电路设计：**
	1. 分析微操作序列：各个周期中的微操作序列（取指、间址、执行、中断）
	2. 选择CPU控制方式：定长/不定长；定长--确定每个机器周期内的节拍数
	3. 安排微操作时序：把几个微操作分配在同一个节拍中
		- 微操作顺序保持不变
		- 访问对象不同-尽量同时钟周期
		- 微操作时间短的-尽量同时钟周期
	4. 电路设计
		1. 列出操作时间表
		2. 写出最简表达式
		3. 画逻辑图

- **特点：**
	- 指令越多，设计和实现就越复杂，因此一般用于RISC（精简指令集系统）
	- 硬件已经定死，扩充指令较困难。
	- 纯硬件实现控制，执行速度很快。微操作控制信号由<u>组合逻辑电路</u>即时产生。

### 2、微指令的设计
1. 水平型：**操作控制字段 + 顺序控制字段**
	- 定义多个微命令；<u>操作控制字段</u>较长，因此每条指令较宽
	- 微程序长，执行快，编写麻烦，并行性强
2. 垂直型：微操作码μOP + 目的地址Rd + 源地址Rs
	- 对应一个微命令；但是一个微程序中有更多多条微指令
	- 微程序短，执行慢，编写简单
3. 混合型   
> 微指令的性质——<u>相容性：可并行 / 互斥性：不可并行</u>

- **水平型微指令-控制字段的设计方式：**

	2. **字段直接编码**：缩短了微指令字长；需要译码，速度较慢
	3. 字段间接编码（隐式编码）：进一步缩短字长；削弱了并行控制能力，速度更慢

> 类似硬布线，但不用设计电路

2. 写出对应微操作命令的节拍安排

1. 静态微程序：微程序无需改变，ROM
	动态微程序：通过改变微指令和微程序来修改机器指令，EPROM
2. 豪微程序：将微程序再细分

### **硬布线与微程序的比较**

|      | 微程序控制器                                | 硬布线控制器                                |
| ---- | ------------------------------------- | ------------------------------------- |
| 工作原理 | 微操作控制信号以微程序的形式<br>存放在控制存储器中，执行指令时读出即可 | 微操作控制信号由组合逻辑电路<br>根据当前的指令码、状态和时序，即时产生 |
| 执行速度 | 慢                                     | 快                                     |
| 规整性  | 规整                                    | 较繁琐                                   |

# 五、异常和中断机制
> [中断和异常](408考研复习/操作系统-408/第1章%20概要.md#中断和异常)
> [程序中断方式](408考研复习/计组原理-408/第7章%20输入输出系统.md#程序中断方式)

### 中断的分类
1. 按信号来源分类：
	- **内中断**（**异常**）【中断信号来自cpu内部】
		1. 陷阱 trap
		2. 故障 fault
		3. 终止 abort
	- **外中断**【中断信号来自硬件】
		1. 时钟中断：表示时间片完成，用于计时、进程调度等
		2. I/O中断：表示I/O操作完成
2. 按触发原因分类：
	- **硬故障中断**：硬件引起，eg控制器出错、存储器校验错、总线错误——abort、外中断
	- **程序性中断**：软件中断，eg除零、溢出、断点、单步跟踪、非法指令、栈溢出、地址越界、指令译码非法操作码、缺页——fault
3. 按自愿性分类：
	- 自愿——trap
	- 程序性——fault
### 异常（内中断）
> cpu执行指令过程中内部检测到的同步事件，具有确定性

1. **故障fault**：指令启动后，执行过程中检测到响应故障
	- 缺页、用户态执行访管指令
2. **自陷trap**：（自陷、陷入）正常执行完毕，主动转入操作系统内核
	- x86系统调用的访管指令syscall
	- minps条件自陷指令teq
3. **终止abort**：严重硬件故障
### 中断（外中断）
> 外部设备（I/O设备，定时器）发起的异步请求，在指令执行结束后才会响应，具有随机性

- 可屏蔽中断 / 不可屏蔽中断：是否可以被软件屏蔽
- 向量中断 / 非向量中断：硬件提供地址 / 软件轮询确定中断源
- 单重中断 / 多重中断

### 异常和中断的响应过程
> - 触发时机：异常由当前指令引发--同步；中断与指令无关--异步
> - 检测机制：异常由自动检测或软件触发；中断由外部硬件通过‘<u>中断请求线</u>’发送给cpu
> - 响应过程由硬件自动完成——硬指令，响应结束后由操作系统内核软件实现
1. 关中断：IF=0关中断，IF=1开中断
2. 保存断点和程序状态：程序状态字PSW（包括条件码、中断允许标志、特权级等）
> 中断的断点位置：
> - 故障——当前指令位置
> - 陷阱——下一条指令
> - 终止——当前或下一条
> - 外中断——下一条指令
3. 识别事件并转移到转移程序
	- 早期-软件轮询
	- 现代-硬件向量机制（向量中断）

**4、流水线的分类**
1. 按使用级别分
	- 部件功能级：将算术逻辑运算组成流水线形式（如浮点加法->求差、对阶、尾数相加以及结果规格化等4个子过程。
	- 处理机级：把一条指令解释过程分成多个子过程，（如取指、译码、执行、访存及写回5个子过程）
	- 处理机间：是一种宏流水，其中每一个处理机完成某一专门任务，各个处理机所得到的结果需存放在与下一个处理机所共享的存储器中
2. 按功能分：单功能 / 多功能
3. 按同一时间内流水线各端的连接方式：静态（相同） / 动态（不同）
4. 按是否有反馈信号：线性（无） / 非线性（有反馈回路）
### 流水线的多发技术
 1. 超标量技术：通过编译优化，把可并行指令搭配起来
	 - 每个时钟周期并发多条指令
	 - 配置多个功能部件
	 - 不能调整指令执行顺序
		<img src="/personal-blog/images/QQ_1783304758053.png" width="350">
 2. 超流水技术：时分复用
	 - 一个时钟周期内再分段
	 - 一个时钟周期内功能部件用n次；指令速度是段数的n倍
	 - 不能调整指令执行顺序
		<img src="/personal-blog/images/QQ_1783304871535.png" width="350">
3. 超长指令字：
	- 编译程序发现指令间的并行性，把多条指令合并为一条（多达几百位
	- 多个处理部件
	- 不能调整指令执行顺序

> **乱序发射**：cpu在译码后，送入执行单元时，优先把操作数就绪、无冲突的指令发送去计算
### 流水线冲突类型与解决方法
1. 结构相关--资源冲突(结构冒险)：多条指令争抢同一资源【互斥】
	1. 相关指令暂停：后一指令暂停一周期
	2. 资源重复：如把cache分为数据存储和指令存储，即可避免冲突
2. **数据相关--数据冲突**：两条指令有先后顺序（后条指令的数据未就绪）【同步】
	1. 相关指令暂停，直到数据冲突消失：1. 硬件阻塞stall 2. 软件插入NOP【空指令】
	2. 数据旁路技术：硬件添加通路
	3. 编译优化：编译器调整指令顺序
3. 控制相关--控制冲突：遇到转移指令（PC值改变）
	1. 转移指令分支预测：简单预测；动态预测
	2. 预先获取转移成功 / 转移不成功 两种情况控制流的目标指令
	3. 加快和提前形成条件码
	4. 提高转移方向的猜准率

> **锁存器**：每段后都有一个缓冲寄存器，保存本流水段的执行结果

1. 运算类指令
> <img src="/personal-blog/images/QQ_1783306432770.png" width="510">
	- IF：根据PC从指令Cache取指令至IF段的锁存器
	- ID：取出操作数至ID段锁存器
	- EX：运算，将结果存入EX段锁存器
	- M：空段
	- WB：将运算结果写回指定寄存器

2. LOAD指令
> <img src="/personal-blog/images/QQ_1783306650927.png" width="287">
	- IF：根据PC从指令Cache取指令至IF段的锁存器
	- ID：将基址寄存器的值放到锁存器A，将偏移量的值放到imm
	- EX：运算，得到有效地址
	- M：从数据Cache中取数并放入锁存器
	- WB：将取出的数写回寄存器

3. STORE指令
> <img src="/personal-blog/images/QQ_1783306913069.png" width="282">
	- IF：根据PC从指令Cache取指令至IF段的锁存器
	- ID：将基址寄存器的值放到锁存器A，将偏移量的值放到Imm。将要存的数放到B
	- EX：运算，得到有效地址。并将锁存器B的内容放到锁存器Store。
	- M：写入数据Cache
	- WB：空段

4. 条件转移指令【相对寻址】
> <img src="/personal-blog/images/QQ_1783307318217.png" width="590">

	- ID：进行比较的两个数放入锁存器A、B；偏移量放入 Imm
	- EX：运算，比较两个数
	- M：将目标PC值写回PC
	- WB：空段

5. 无条件转移指令
> <img src="/personal-blog/images/QQ_1783307571175.png" width="370">
	- 无条件转移指令
	- IF：根据PC从指令Cache取指令至IF段的锁存器
	- ID：偏移量放入Imm

# 七、多处理器
> 只考选择

### 计算机体系结构
1. 单指令流单数据流 SISD：顺序执行指令，并发但不并行
	- 1单核处理器+1存储器
	- 采用多模块交叉存储器，可实现指令流水线
2. 单指令流多数据流 SIMD：**数据级并行**，<u>对不同数据进行大量重复处理</u>
	- 一个指令控制单元CU+多个处理单元+多个局部存储器+一个主存储器，多个处理单元的寄存器可以存放多个数据，但是只能执行一条指令
	- 应用--**向量处理机**：流水化，可直接计算一维向量数据，用于科学研究
3. 多指令单数据流 MISD：少见
4. 多指令多数据流 MIMD：常见，**线程级并行**，各指令序列并行执行
	1. 多计算机系统（消息传递型MIMD）：每个节点私有存储器和地址空间，依赖**消息**传递数据
	2. 多处理器系统（共享存储型MIMD）：共享存储，地址统一，LOAD，STORE指令可以直接访问其他存储器
-----------------
-  多核处理器
> 将多个独立的处理单元集成到单个cpu上，每个处理单元称为核core，每个核有私有的L1Cache，共享一个LLC（最低一级的cache）
> 多线程：确保每个核都执行线程，提高效率

-  共享内存多处理器 SMP：共享单一物理地址空间的多核处理器，
	- 统一存储访问UMA多处理器：所以cpu访问任意单元延迟相同
	- 非统一存储访问NUMA多处理器：主存分区域连接不同cpu
>物理地址统一，而虚拟地址可以分cpu独立，操作系统进行虚拟地址的映射

### 硬件多线程
1. 细粒度多线程：处理器在每个时钟周期切换线程
2. 粗粒度多线程：连续执行同一线程的指令序列，只有阻塞（如cache缺失）时才切换线程
3. 同时多线程SMT：一个时钟周期发射多个线程的指令
<img src="/personal-blog/images/QQ_1783578004958.png" width="730">

> **超线程技术**：在cpu内部复制必要的线程资源，共享cpu的高速缓存和功能部件，使线程并行运行【单核模拟双核】
